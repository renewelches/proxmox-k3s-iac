# proxmox-terraform-k3s

Infrastructure-as-code for deploying a k3s cluster on Proxmox VE using Terraform and Ansible.

## Overview

Terraform provisions the VMs on Proxmox via cloud-init (static IP, gateway, SSH key, user) and generates Ansible inventory files. Ansible installs and configures k3s — server first, then agents which join automatically using the server-generated token.

## Structure

```text
.
├── terraform/
│   └── environments/
│       ├── proxmox-prod/k3s/   # Production: full resources, MinIO backend
│       └── proxmox-dev/k3s/    # Dev: reduced resources, local backend
└── ansible/
    ├── deploy-k3s.yml
    ├── files/k3s-config/
    └── inventory/
        ├── prod/k3s/           # Generated by proxmox-prod terraform apply
        └── dev/proxmox/k3s/    # Generated by proxmox-dev terraform apply
```

## Environments

| Environment | vCPU (server/agent) | RAM (server/agent) | Disk  | Backend    |
|-------------|---------------------|--------------------|-------|------------|
| prod        | 4 / 4               | 8192 / 8192 MiB    | 50 GB | MinIO (S3) |
| dev         | 2 / 1               | 2048 / 1024 MiB    | 20 GB | local      |

## Terraform State Backend

For production it is recommended to use MinIO as a remote S3-compatible backend to keep state off local disk and enable team collaboration. The prod stack is pre-configured for this — copy `backend.tf.example` to `backend.tf` and fill in your MinIO credentials before running `terraform init`.

A full MinIO setup for Proxmox (LXC-based) is available at:
**[renewelches/proxmox-lxc-iac](https://github.com/renewelches/proxmox-lxc-iac)**

The dev stack uses a local backend — no MinIO required.

## Workflow

### 1. (Optional) Provision MinIO

Follow [renewelches/proxmox-lxc-iac](https://github.com/renewelches/proxmox-lxc-iac) to deploy MinIO on Proxmox, then create a `terraform-state` bucket. Skip this step for dev.

### 2. Provision VMs with Terraform

```bash
cd terraform/environments/<proxmox-prod|proxmox-dev>/k3s
cp terraform.tfvars.example terraform.tfvars   # fill in values
cp backend.tf.example backend.tf               # prod: fill in MinIO credentials
terraform init
terraform apply
# Generates: ansible/inventory/<prod|dev/proxmox>/k3s/inventory.ini
```

Key variables to set in `terraform.tfvars`:

| Variable         | Description                                  |
|------------------|----------------------------------------------|
| `proxmox_api_url`| Proxmox API endpoint                         |
| `proxmox_nodes`  | Map of role → Proxmox node name              |
| `static_ips`     | Map of role → CIDR IP (e.g. `192.168.86.105/24`) |
| `gateway`        | Default gateway for all VMs (e.g. `192.168.86.1`) |
| `ci_user`        | VM user created by cloud-init                |
| `ci_ssh_key`     | Path to your SSH public key (e.g. `~/.ssh/id_ed25519.pub`) |
| `k3s_template_ids` | Map of Proxmox node → template VM ID      |

### 3. Deploy k3s with Ansible

```bash
ANSIBLE_CONFIG=ansible/inventory/<prod|dev/proxmox>/k3s/ansible.cfg \
ansible-playbook -i ansible/inventory/<prod|dev/proxmox>/k3s/inventory.ini \
  ansible/deploy-k3s.yml
```

## How the k3s token works

No token is pre-configured. k3s auto-generates one on the server at startup. The Ansible playbook reads it from `/var/lib/rancher/k3s/server/node-token` and injects it into each agent's config before installation — agents join automatically.

## Prerequisites

- Proxmox VE with a VM template cloneable via the `bpg/proxmox` Terraform provider
- Cloud-init enabled on the template (for user, SSH key, IP, and gateway injection)
- Ansible with SSH access to the provisioned VMs
- MinIO with a `terraform-state` bucket (prod only) — see [renewelches/proxmox-lxc-iac](https://github.com/renewelches/proxmox-lxc-iac)
