# Ansible

Deploys and upgrades k3s on VMs provisioned by Terraform.

## Playbooks

### `deploy-k3s.yml`

Installs k3s on all nodes in four plays:

1. **Prepare all nodes** — apt update/upgrade, create `/etc/rancher/k3s/`
2. **Deploy k3s server** — install k3s server, wait for it to be ready, retrieve the auto-generated token
3. **Deploy k3s agents** — inject the server token, install k3s agent, verify it joins the cluster
4. **Fetch kubeconfig** — copies `/etc/rancher/k3s/k3s.yaml` to `~/.kube/config-k3s` on localhost and rewrites the server address from `127.0.0.1` to the actual server IP

No token needs to be pre-configured — k3s generates one automatically and Ansible propagates it to agents.

Pass `k3s_version` to pin a specific release; omit it to install the latest stable:

```bash
ansible-playbook -i inventory/prod/k3s/inventory.ini deploy-k3s.yml -e "k3s_version=v1.32.3+k3s1"
```

**Private registry (optional).** If `k3s_registry_host` is defined, the prepare
play renders `files/k3s-config/registries.yaml.j2` into
`/etc/rancher/k3s/registries.yaml` (mode `0600`) on **every** node so containerd
can authenticate image pulls. Omit `k3s_registry_host` to skip it entirely. On
an already-running cluster the file change restarts k3s so containerd reloads it.

The defaults target GCP Artifact Registry with a service-account key: username
`_json_key_base64` and the base64-encoded `key.json` as the password. The key
file lives outside this repo (`k3s_registry_key_file`) and is embedded at render
time, so no credential is committed. Set the vars in
`inventory/<env>/k3s/group_vars/all.yml` (see `all.yml.example`):

```yaml
k3s_registry_host: europe-west1-docker.pkg.dev
k3s_registry_key_file: /path/to/key.json
# k3s_registry_username: _json_key_base64   # default
```

| Variable | Default | Description |
|---|---|---|
| `k3s_registry_host` | — (unset ⇒ skipped) | Registry endpoint, e.g. `europe-west1-docker.pkg.dev` |
| `k3s_registry_key_file` | — | Path on the control machine to the GCP service-account `key.json` |
| `k3s_registry_username` | `_json_key_base64` | containerd auth username |

### `deploy-metallb.yml`

Installs [MetalLB](https://metallb.universe.tf/) and configures an L2 address pool, so `Service type=LoadBalancer` gets a real IP from your network.

Three plays:

1. **Disable ServiceLB** — re-renders the server config with `disable: servicelb` and restarts k3s, so the bundled k3s ServiceLB (Klipper) stops competing with MetalLB for LoadBalancer IPs. Toggle with `k3s_disable_servicelb` (default `true`).
2. **Install MetalLB** — applies the pinned upstream `metallb-native.yaml`, then waits for the controller (its webhook) and the speaker DaemonSet to be ready.
3. **Configure the pool** — renders `files/metallb/metallb-pool.yaml.j2` into an `IPAddressPool` + `L2Advertisement` and applies it (retried until the webhook accepts it).

`metallb_pool_addresses` is **required** — set it in `inventory/<env>/k3s/group_vars/all.yml` (see `all.yml.example`) or pass it inline:

```bash
ansible-playbook -i inventory/prod/k3s/inventory.ini deploy-metallb.yml \
  -e '{"metallb_pool_addresses": ["192.168.1.240-192.168.1.250"]}'
```

| Variable | Default | Description |
|---|---|---|
| `metallb_pool_addresses` | — (required) | List of IP ranges/CIDRs for the pool (keep out of any DHCP scope) |
| `metallb_pool_name` | `default-pool` | Name of the `IPAddressPool` / `L2Advertisement` |
| `metallb_version` | `v0.14.9` | Pinned MetalLB release |
| `k3s_disable_servicelb` | `true` | Disable the bundled k3s ServiceLB (Klipper) |

### `upgrade-k3s.yml`

Upgrades an existing cluster to a specific version. `k3s_version` is required.

**Upgrade order:** server first, then agents one at a time (drain → upgrade → uncordon). Nodes already on the target version are skipped.

```bash
ansible-playbook -i inventory/prod/k3s/inventory.ini upgrade-k3s.yml -e "k3s_version=v1.32.3+k3s1"
```

## Config Templates

| File                                     | Applied to                                     |
|------------------------------------------|------------------------------------------------|
| `files/k3s-config/config-server.yaml.j2` | Server node                                    |
| `files/k3s-config/config-agent.yaml.j2`  | Agent nodes                                    |
| `files/k3s-config/registries.yaml.j2`    | All nodes (only if `k3s_registry_host` is set) |
| `files/metallb/metallb-pool.yaml.j2`     | MetalLB `IPAddressPool` + `L2Advertisement`    |

## Inventory

### prod

```
ansible/inventory/prod/k3s/
├── ansible.cfg        # StrictHostKeyChecking=accept-new
├── inventory.tpl      # Terraform template
├── inventory.ini      # Generated by terraform apply (git-ignored)
└── group_vars/
    ├── all.yml.example # Env var template (committed)
    └── all.yml         # Your real values, e.g. MetalLB pool (git-ignored)
```

### dev (Proxmox)

```
ansible/inventory/dev/proxmox/k3s/
├── ansible.cfg        # StrictHostKeyChecking=no
├── inventory.tpl      # Terraform template
├── inventory.ini      # Generated by terraform apply (git-ignored)
└── group_vars/
    ├── all.yml.example # Env var template (committed)
    └── all.yml         # Your real values (git-ignored)
```

## Usage

```bash
# Deploy (latest stable k3s)
ansible-playbook -i inventory/prod/k3s/inventory.ini deploy-k3s.yml
ansible-playbook -i inventory/dev/proxmox/k3s/inventory.ini deploy-k3s.yml

# Deploy (pinned version)
ansible-playbook -i inventory/prod/k3s/inventory.ini deploy-k3s.yml -e "k3s_version=v1.32.3+k3s1"

# Install MetalLB (pool from group_vars/all.yml)
ansible-playbook -i inventory/prod/k3s/inventory.ini deploy-metallb.yml

# Upgrade existing cluster
ansible-playbook -i inventory/prod/k3s/inventory.ini upgrade-k3s.yml -e "k3s_version=v1.32.3+k3s1"
```
